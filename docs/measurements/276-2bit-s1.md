# Measurement 276 S1: the 2-bit (ternary, QS2CX_WH) Gemma-4 26B file on the device, E and A

Issue #276. Plan: `docs/plans/276-2bit-experts-rev3.md` (branch `htp/276-plan`, PR #277)
§4 S1. Runner `276-run.sh` (sources `260-e-run.sh`), file check `276-qs2cx-check.py`.

**Result.** The 2-bit expert file loads and runs on the S25: #4415's prefill and our
one-PD decode (E), and #4415's hybrid (A), on the same build. The expert arena is
704 MiB at C = 16, half of the 4-bit 1 408. E decode at p512 G512 C = 16 is **9.76 tok/s**,
against 4.98 for the 4-bit file. Miss wait fell from 115.7 to 29.3 ms/token at more
misses (128.6 against 95.0/token). Most misses were served from the page cache, not from
flash (0.18 MiB of `pgpgin` a miss, not ≈ 1.45). E prefill is 190 / 195–197 tok/s
at p512 / p1024 (A: 180 / 177). Two gaps came up, both outside the plan's one gap:

1. **The file's head is untied** (`tie_word_embeddings: false`). Only `tie_word_embedding`
   called the HTP decode hook, so every E cell died at the first decode row:
   `decode_op_fp32: pos moved to 513 with the stretch input of op 0 pending`.
   Commit `28f5d96ef` makes `lm_head` call the same hook.
2. **No nll on this file.** `NNTR_PPL` is implemented only in `tie_word_embedding`. The
   PPL cells (E and A, p512 G64) ran but printed no `nll/token`. The nll gate is
   **unavailable**, not passed.

**Base.** `htp_decode` @ `15a084a7d`: #4415 @ `41bd65e04` prefill + our one-PD decode +
#271 readers + #272 bypass + the 1k/2k/4k runner + #274. The current head `19dbf3a78`
(revision 3, #4415 @ `2db6cad59`) was not used: it crashes on the device at the MoE
warm-up (DSP heap, under investigation).

## Reading

- **Speed is not a clean byte comparison.** The 4-bit file (12.8 GB) cannot sit in the
  phone's page cache; most of this 7.5 GB file can. At C = 16 a miss brought in 0.18–0.56 MiB
  of `pgpgin` against a 1.45 MiB expert: most misses were page-cache hits. At C = 32 the
  arena takes another 704 MiB, the cache shrinks, and `pgpgin` per miss rises to
  1.01–1.18 MiB.
- **C = 32 at the same arena bytes (plan L2).** It halves the misses as the simulator says
  (128.6 → 69.6 at p512; 109.9 → 47.4 at p1024). It still decodes slower, 8.55 against 9.76
  and 7.20 against 7.49, because its misses go to flash (miss wait 42.6 against 29.3 ms).
  Plan §3.4 picked C = 32 assuming every miss reads flash. On this file and this phone the
  page cache changes that. C = 16 is the faster row here. **This is a cache-state result,
  not a steady state.** The cells ran back to back, and the page cache held what the
  earlier cells read. A cold-cache cell (evict first, `tools/htp/page_cache_evict.c`)
  answers it. Not run.
- **Different text, different routing.** misses/token at p512 is 128.6 here against 95.0
  on the 4-bit file at the same C. The two files route differently, as the plan expected.
  The decode tok/s are read beside each other, not as an A/B.
- **Prefill (E ≥ 0.95 × A, same file, same build): pass.** 189.7 / 180.3 = 1.05 at
  p512; 194.7 / 176.9 = 1.10 and 196.8 / 176.9 = 1.11 at p1024. Against the 4-bit E:
  p512 189.7 against 147–157, p1024 195–197 against 191.5.
- **Load.** E loads the FC arena in 830–882 ms with no re-quantization (the QS4CX FCs bind
  directly). Arena 704 MiB at C = 16 and 1 408 at C = 32, as plan §3.4 predicted.
  `heap_used_kib` is 1.42–1.47 M. Peak RSS is 3.30 GB for E and 2.94 GB for A.

## Text (judged to the first `<turn|>`; `260-turn106.py`)

- **p1024: coherent in E and A, and on topic** (the Ardley harbour-town summary).
  - E (C 16 and C 32 give the same tokens, so the pool is exact): "The small harbour town
    of Ardley, located where a river meets the northern sea, is a resilient community
    shaped by a history of fishing, farming, and frequent weather extremes. … From its
    12th-century origins to its modern era of wind turbines …". It ends on `<turn|>` at
    125.
  - A: "The small harbor town of Ardley, located near a river and sea, is a community
    defined by its maritime and agricultural history …".
  - E and A diverge at the first decode token. This is the same pattern the 4-bit r2
    sitting recorded: the decode FC paths are not bit-identical by construction (plan 260
    §7.3). **Verdict: pass (coherent); token equality E == A: no, by construction.**
- **p512: degenerate in both E and A, from the first decode token.**
  - A: "He (the author) is actually, as a thought, a part of the text. …", which turns
    into "( ( ( (" loops. Loop onset (`260-loopstart.py`) at token 36.
  - E: "Lhe most important part of this summary Lhe most …". Onset at 52.
  - Neither reaches `<turn|>`. The 4-bit file gave a coherent p512 summary in both
    modes (260 r2). A, which is #4415's own decode, fails on this prompt too, so this is
    not attributed to the one-PD decode. Its cause (the file at this prompt, or this tree
    on this file) is open.
  - **Verdict: fail for both, user approval needed.** This is the first thing to answer
    before any accuracy claim on this file.
- **nll / decode PPL: not measured** (gap 2). The anchor nll 4.5562 (doc 55 §10.8) cannot
  be compared yet.
