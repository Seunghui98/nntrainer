# Measurement 282 B: free the CPU-side FC copies (A), next-layer prefetch (B), 2-bit file, S25

Issue #282 (user decisions 2026-10-09: drop the CPU copies; implement the residual-based
next-layer prefetch; no S26). Branch `htp/282-b` = `htp/282-no-flash` @ `f55f5b28e` +
A `c7681c73c` (`NNTR_HTP_DROP_HOST_FC`) + B `6a3ba09b1` (hint slot + `NNTR_MOE_PREFETCH`).
Each is a commit of its own and off by default.

Cell: E p1024 G512, file `gemma4_26b_ternary_fcqs4cx`, q8 KV, init_seq_len = prompt + G
(`s282cfg/`), #267 L3 on. S25 `R3CY205ZMND`, 2026-10-09 18:1x–18:4x KST, `COOL_QUICK`.
Logs `scratchpad/r276/P/<cell>.log`, runner `282-run.sh one`. No PC gates.

**Result.**

- **A pays.** The one-PD token never reads 1 182 MiB of the app's heap: the FC / dense /
  untied-head weights, after their arena and WH copies exist. At the first decode token
  these pages go back.
  - MemAvailable: 1 355–1 458 → 2 543–2 646 MiB at C = 32.
  - The page cache keeps more experts: `pgpgin` a miss 1.34 → 0.84 MiB at C 32, and
    0.26 MiB at C 16.
  - Miss wait 45.3 → **28.9–29.0 ms**.
  - Decode 6.86 → **7.82–7.86 tok/s** overall, 9.60 → **11.30–11.41** steady.
  - Ids unchanged.
- **B does not pay. B is implemented as specified below.**
  - 59 % of the misses were prefetched (29.3 of 49.9 a token). Even so, miss wait was
    29.0 ms off and 30.3–31.1 ms on, and decode was 10.4–10.8 against 11.4 steady.
  - The guess router alone (`NNTR_HTP_PREDICT=1`, no prefetch) reads 30.1 ms / 10.6
    steady. **The loss is the extra router on the DSP.** The prefetch itself is neutral
    (1 reader thread: 30.3 ms).
  - At C 16 it is worse: miss wait 36.8 → 45.9 ms with 4 readers. There, flash bytes per
    miss rose 0.26 → 0.42 MiB. That the readers compete with the pool server for ARM cores
    is a hypothesis, not measured.
  - Ids unchanged in every cell.

**How B is built.** The slot / table protocol is untouched. The guess is posted to a new
mailbox slot (`htp_pred_hint`, 128 B after the miss answer; `HEXKL_MBOX_BYTES` 18 432 →
18 560 inside the 64 KiB page; no IDL change). `graph_predict` posts it at layer L's
router, without a wait. The pool server takes the newest hint between its miss polls, and
`NNTR_MOE_PREFETCH` reader threads pread the guessed experts the pool lacks into the page
cache. The true miss a layer later is then a DDR pread.

This deviates from the request, which was to copy the guess into LRU-tail slots. Doing
that needs S1 to accept rebinds outside a miss round. The page-cache form gets the same
flash-overlap and cannot move the ids.

## Reading

- **Step A.** The 1 182 MiB of FC / dense / head copies are exactly the
  `q4_pending_` weights (206). A tied head (the embedding table) is skipped.
  - The embedding (415 MiB) and the fp16 KV master that ATTN_M1 seeds from stay.
  - The rest of the 1.7 GB RSS after the drop is not itemised.
  - ponytail (in the code): a second prefill that fell back to a CPU FC would read zeros.
    The knob is for single-prompt runs.
- **Step B.** The coordinator's host estimate was miss wait ≈ 46 → ≈ 25 ms at C 32. The
  device reads 29.0 → 30.3–31.1.
  - 29 of the 50 misses a token were prefetched, so the guess works.
  - The prefetch reads overlap the true misses' reads. Most of what the misses wait on is
    the pool server's round trip (≈ 1.3 ms × 22 rounds), not the bytes.
  - The guess router adds DSP time: steady 87.6 → 94.1 ms a token, of which miss wait is
    +1.1, so ≈ 5 ms is the router.
  - Under these numbers lever 3 stays closed. The open question is the round count, not
    the bytes.

## Next

  spin window are the levers.
