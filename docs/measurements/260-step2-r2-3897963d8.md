### Pool misses: DSP compute, flash wait and ARM separated

`miss_wait` is S1's own wall time from posting a miss request to the ARM's answer, in QTimer
µs (`hexkl_token.c` `tk_miss_wait`). The DSP thread sleeps through it. The per-kind ms above
are pcycles divided by the run's average clock, and that average includes the sleeping
waits. So the split that holds is in wall time:
- **DSP non-wait = wall − miss_wait**: every kernel's compute.
- **miss_wait**: the flash read plus the ARM's pool round.
- **ARM outside the call** (`arm_us`): the layer walk, sampler and print between two tokens.

The per-token rate comes from the G64 → G512 difference:
- p512: (51,365 − 28,405) / 105 = **219 MiB/token refaulted**, against the driver's
  233 MiB/token `pgpgin`;
- p1024: (170,303 − 28,076) / 448 = **317 MiB/token**, against 309.

So the experts the misses read were in the page cache earlier and have been evicted since.
The 12.8 GB file does not stay cached on this 11.1 GB unit. The miss path reads flash, and
the file cache cannot absorb it.

**Reading.**
- **E's decode is flash-bound.** At C = 16 a token waits 208–306 ms for 95–121 expert misses,
  2.2–2.7 ms per miss. That is 70–77 % of the token. The DSP's own compute is 80–94 ms per
  token. The ARM outside the call is 1.3–1.8 ms.
- The pool rounds are about one per MoE layer (28.6–29.6 per token for 30 layers). Each one
  is 7.7–10.7 ms of ARM read.
- The bytes read from flash are 2.4–2.8 MiB per miss (`pgpgin`), which is about a whole
  expert slot. The S1 pool is 1408 MiB / (30 × 16) = 2.93 MiB per slot. The expert is
  3 × 2816 × 704 × 4 bit = 2.97 MB plus scales.
- **The 1.52 MB per expert given for the read rate is about half the slot.** The implied rate
  is shown both ways. Measured from `pgpgin` over the wait, it is about 1.0–1.1 GiB/s.
- Without the waits, the DSP non-wait time alone would allow 1000 / 80.6 = 12.4 tok/s at
  p512 and ≈ 10.8 at p1024 (arithmetic, not measured).

**DSP compute inside the 80.6 ms (E p512 G512).**
- The non-MOE kinds hold 118.2 M of the 340.4 M pcyc per token. MOE's 222.2 M pcyc include
  the sleeping wait loop.
- The per-kind ms in the table above are therefore upper bounds on compute only for MOE.
  The other kinds are ms at an average clock that the waits pull down.
- Fitted into the 80.6 ms non-wait budget, the non-MOE kinds imply a compute clock of at
  least 1.47 GHz. P4 ran at 2.09 GHz.
- At 2.09 GHz the non-MOE compute would read:
  - FC 19.4 ms, ATTN_M1 12.1, DENSE_FFN 9.9, LM_HEAD 8.3, ROUTER_TOPK 3.2, RMSNORM 2.2,
    QK_NORM 0.7, ADD 0.4, ROPE 0.3 (sum 56.5 ms);
  - plus the MoE compute, which the logs cannot split from the wait.
- Note: ATTN_M1 doubles from p512 to p1024 (KV length).

## Verdict

- E runs end to end on the real 26B file on the NPU. `calls/token = 1.00` in every E cell,
  with no load failure at C = 16. **E's decode is 2.5–3.3 tok/s, not the 15 tok/s the plan
  expected.** P4's dummy routing hit its cache. On real routing, C = 16 misses 95–121 experts
  per token, and the flash waits are 70–77 % of the token.
- E vs A, same sitting:
  - decode: E +9 % at p512 G512 (3.33 vs 3.04, over E's 169 tokens), +2 % at p1024 G512
    (2.58 vs 2.53);
  - prefill: E 0.91–1.03 × A.
- Text: pass for both. nll: E == A (4.573 / 3.618). Router gate: fail.
- C stays 16 (user, 2026-10-09). The one C = 24 cell that ran does not fit the one PD
  (ENOMEMORY when the second attn_m1 set registers).
- The decode misses are page-cache refaults: refault ≈ pgpgin, ≈ 220–320 MiB/token.
- The next lever for E is the miss read path: how the ARM reads the misses (about one round
  per layer, 7.7–10.7 ms each), overlapping those reads with compute, and the bytes per
  expert. C stays 16. It is not DSP compute.
