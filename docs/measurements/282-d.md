The quantized prefill caches are as large as the fp16 attn_m1 cache: 4 int8 arrays (K / V

heap failing to place attn_m1's two 200 MiB blocks beside those caches.

## Reading

- **Speed.** int8 halves ATTN_M1 at p1024: 20.9 → 11.4–11.6 ms. At p2048, 26.6 → 13.4. The
  kernel is the fp16 one with an unpack + convert on each load: PV reads half the bytes.
- **Memory.** heap_used falls by ≈ 230 MiB at C 32. With the quantized caches released,
  C 40 loads at p1024, and C 32 at p2048. Steady decode at p1024 C 40 is **13.4 tok/s**
  (11.3 at fp16 C 32).
- **The C ceiling is now the prefill.** The prefill's MoE scratch fails at C 44 (p1024) and
  C 40 (p2048), and FC set mapping fails at C 48. The heap the decode needs is no longer
  what binds.
- **p4096.** Moving the quantized caches out of load was enough to load it. The prefill
  then runs out (`res_add err=39`): its own quantized caches are ≈ 894 MiB at 4 160 rows
  beside the prefill workspace. The next lever is to size those caches to the prompt
  (prefill-only rows; decode uses attn_m1). That is not done here.
- **Accuracy.** The gate is text only. `NNTR_PPL` scores no untied head, so there is no
  nll on this file.
  - Margin 1.25 looped at p2048; 1.0 does not. That is one reading per setting, so the
    margin is a knob that still needs a PPL gate before it is a default.
  - Token equality against the fp16 cell is not expected.

## Copy-path levers for a later step (from 282 C)

1. **A cached ION arena with an explicit clean before the answer.** The miss copy into
   the uncached arena runs at 3.7–4.9 GB/s, and is ≈ 0.7–0.9 ms of a 1.3–1.7 ms round.
2. **More page cache.** The flash share of a miss is 0.6–1.1 MiB. Every MiB the arena or
   the heap gives back goes to the page cache. The arena itself is the same RAM, so C buys
   hits without copies but takes page cache.
