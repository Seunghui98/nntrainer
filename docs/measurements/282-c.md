**Result: the round trip is not the miss wait; the read is.** Per round (≈ 2.25 experts,
22 rounds a token), every latency term together is ≈ 70 µs:

| part | µs a round | where it is measured |
|---|---|---|
| DSP post → ARM pool server noticed it | **1** | ARM `cntvct_el0` − the post's QTimer stamp (same 19.2 MHz counter) |
| ARM before the reads (harvest, policy, stage) | 5–7 | ARM steady clock |
| **ARM reads the misses into the arena (4 readers)** | **1 592–1 726** | ARM steady clock around `readMisses` |
| ARM total (answer written) | 1 598–1 733 | `arm_ms/round` |
| DSP: present experts computed between post and wait (L3) | 307–320 | DSP QTimer, post → wait start |
| DSP waits | 1 306–1 436 | `miss_us` / rounds |
| answer written → DSP saw it | 19–21 | DSP QTimer − the answer's `cntvct_el0` stamp |
| DSP rebinds after the answer | 24–25 | DSP QTimer |

The reads are ≈ 99 % of the ARM's round. The present set does run before the wait (L3's
split, confirmed in `graph_moe_miss`: post, present rows, then wait), and it hides
≈ 0.3 ms a round. The pool server's poll costs ≈ 1 µs. The DSP's spin / sleep after the
answer costs ≈ 20 µs.

**So the coordinator's levers 2a / 2b are not worth a commit.** They are the pool server's
poll, its thread priority / affinity, and the DSP spin budget. Together they can win at
most ≈ 45 µs a round, ≈ 1 ms a token.

## What bounds the read

- At C = 32 a round reads 2.25 × 1.45 MiB = 3.3 MiB in 1.6–1.7 ms ≈ **2.0 GB/s**, with
  0.84 MiB a miss still coming from flash.
- At C = 16, with the page cache holding more (`282-b.md` A: 0.26 MiB a miss), a round
  reads 3.8 × 1.45 MiB = 5.5 MiB in 1.49 ms ≈ **3.7 GB/s**.
- That is near the ≈ 4.9 GB/s that #46 / doc 52 §10.9 measured for copies into the
  uncached ION arena.

The read has two terms:

1. **The flash share of the bytes.** Its lever is page cache, i.e. RAM: 282 B's drop
   moved it 1.34 → 0.84 MiB a miss.
2. **The page-cache → uncached-arena copy**, ≈ 0.7–0.9 ms a round at 3.7–4.9 GB/s. Its
   lever is a cached ION arena with an explicit clean before the answer. That is a
   coherence change on the DSP side, not tried here.
